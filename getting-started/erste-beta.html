    Erste Beta — in 15 Minuten zum ersten Agent-PR¶

    Diese Seite führt dich als Beta-Tester vom fertigen Release-Binary bis zum ersten erfolgreich vom Agent erzeugten Pull Request. Lineares Vorgehen, jede Sektion ist Voraussetzung für die nächste.

    Diese Seite ersetzt nicht die Detail-Doku

    Hier liegt der Beta-Pfad. Vollständige Referenzen für Config, Sandbox, Labels etc. siehe Seitenleiste. Bei Problemen → letzter Abschnitt: Bug melden.

    Pre-Flight-Check — bevor du startest¶

    Schnell durchgehen, damit dich nichts mittendrin überrascht:

    • macOS 14+ oder Linux (Ubuntu 22.04+ / Debian 12+)
    • GitHub-Konto + ein Spielwiesen-Repo (kein Produktiv-Code) — Agentry erzeugt darin Branches, Issues-Labels und PRs
    • gh CLI installiert und eingeloggt (gh auth status zeigt deinen Account)
    • Claude Code CLI installiert und eingeloggt (claude --version antwortet)
    • Auf Linux: bubblewrap installiert (sudo apt install bubblewrap)
    • 20–30 Minuten Zeit für den Walkthrough + erstes Beta-Issue

    Wenn ein Punkt offen ist: die Detail-Tabelle unten zeigt, wo du jede Komponente herbekommst.

    Voraussetzungen — was du brauchst¶

    Komponente Wofür Wo bekommen
    macOS 14+ oder Linux (Ubuntu 22.04+/Debian 12+) Daemon-Laufzeit —
    Homebrew Empfohlener Installer für Agentry selbst + gh macOS: vorinstalliert / brew.sh; Linux: docs.brew.sh/Homebrew-on-Linux
    git 2.30+ Worktree-Verwaltung macOS: Xcode CLT (xcode-select --install); Linux: sudo apt install git
    gh CLI GitHub-API macOS/Linux: brew install gh
    Claude Code CLI Agent claude.com/claude-code
    bwrap (nur Linux) Sandbox-Default sudo apt install bubblewrap

    GitHub-Konto mit einem Repo, in dem du Issues + PRs erzeugen kannst.

    1. Binary installieren¶

    Empfohlen: über den Homebrew-Tap, einheitlich für macOS und Linux. Manueller Download aus dem öffentlichen Distribution-Repo torben-erz/agentry-dist funktioniert als Fallback.

    brew tap torben-erz/agentry
brew install agentry
agentry version

    Die Formula lädt ein vorgebautes Binary aus agentry-dist — kein Build nötig. macOS-Binary ist signiert (Developer-ID Torben Daniel Erz) und bei Apple notarisiert, xattr- Workarounds entfallen. Verifikation (optional):

    codesign --verify --deep --strict --verbose=2 $(which agentry)
spctl -a -t install -vv $(which agentry)
# Erwartung: accepted, source=Notarized Developer ID

    # macOS Apple Silicon
gh release download --repo torben-erz/agentry-dist -p "*macos-arm64*"
tar xzf agentry-*-macos-arm64.tar.gz
sudo mv agentry /usr/local/bin/

# Linux x86_64
gh release download --repo torben-erz/agentry-dist -p "*linux-x86_64*"
tar xzf agentry-*-linux-x86_64.tar.gz
sudo mv agentry /usr/local/bin/

agentry version

    agentry-dist ist das öffentliche Distribution-Repo (Source liegt privat) — kein zusätzlicher Zugriff nötig. Linux-Binary ist nicht signiert (Apple-Notarisierung ist nur für macOS relevant).

    2. GitHub-Auth herstellen¶

    gh auth login                # Browser-Auth, Scope `repo` reicht
gh auth setup-git            # damit der Daemon ohne Token-Prompt pushen kann

    Verifikation: gh auth status zeigt deinen Account.

    3. Agent-CLI installieren¶

    Claude Code installieren (Anleitung unter claude.com/claude-code) und einloggen. Test:

    which claude && claude --version

    Sollte einen Pfad und eine Version ausgeben. Wenn claude: command not found: Installations-Doku noch nicht vollständig durchgegangen.

    4. Config anlegen und anpassen¶

    agentry init

    Schreibt ~/.agentry/config.json mit Defaults. Eine Pflichtänderung:

    - "watch": "OWNER/REPO",
+ "watch": "dein-account/dein-test-repo",

    watch zeigt auf das Repo, in dem du den Beta-Test durchspielst. Empfehle ein Spielwiesen-Repo ohne wichtigen Code — der Agent wird darin Branches und PRs erzeugen.

    Optional, aber sinnvoll: agentTimeoutSeconds lassen wie er ist (1800 = 30 min). Validieren:

    agentry config validate

    Erwartung: Konfiguration valide.

    5. Labels im Ziel-Repo anlegen¶

    agentry labels install

    Legt alle Trigger-/Status-Labels im konfigurierten Repo an. Idempotent — wenn ein Label schon existiert, wird es übersprungen.

    6. Daemon starten¶

    In einem dedizierten Terminal:

    agentry

    Erwartete Ausgabe in den ersten Sekunden:

    […] [INFO] [App.swift] Konfiguration geladen — Watch: repo:dein-account/dein-test-repo.
[…] [INFO] [Daemon.swift] Agentry-Daemon startet — Backend: claude-code, Poll-Intervall: 5s, Worker: 1, Revise: an
[…] [INFO] [SandboxRouter.swift] Sandbox 'macos-sandbox' (sandbox-exec) — verfügbar.
[…] [INFO] [GitHubSingleRepoSource.swift] Polling …: 0 Tickets mit Label 'agent-task' gefunden, 0 bereit.

    Wichtig: die Sandbox-Zeile soll verfügbar sagen, nicht nicht verfügbar. Bei Linux ohne bwrap würde der Daemon hier mit SandboxError.defaultUnavailable abbrechen — dann apt install bubblewrap nachziehen.

    7. Erstes Ticket — Issue → PR¶

    In deinem Test-Repo ein Issue anlegen:

    • Title: Beta-Test: README-Hinweis ergänzen
    • Body: 
      Bitte ergänze unten in der README.md eine Zeile:

> Hinweis: Dieses Repo wurde als Agentry-Beta-Test genutzt.

Commit-Message nach Belieben.
    • Label: agent-task

    Im Daemon-Log innerhalb von 5 Sekunden zu sehen:

    […] [INFO] [Daemon.swift] Verarbeitung Ticket #1 (worker 1).
[…] [INFO] [WorkspaceManager.swift] Lege Worktree an: …
[…] [INFO] [ClaudeCodeBackend.swift] ClaudeCodeBackend startet (timeout 1800s).
…
[…] [INFO] [Daemon.swift] Ticket #1 erfolgreich abgeschlossen.

    Auf GitHub: das Issue hat jetzt Label agent:done, ein neuer Branch agent/ticket-1 existiert, und ein PR aus diesem Branch ist offen — der Agent hat die README-Zeile ergänzt und im PR-Kommentar auf das Issue verlinkt.

    8. Revise-Loop testen¶

    Am offenen PR das Label agent-revise setzen, dazu einen Review-Kommentar:

    Mach die Zeile bitte zum Listen-Eintrag (mit - davor).

    Im Daemon-Log:

    […] [INFO] [Daemon.swift] Revise-Lauf für PR #2.
[…] [INFO] [WorkspaceManager.swift] Worktree für Head-Branch agent/ticket-1 anlegen…
…
[…] [INFO] [Daemon.swift] Ticket revise: erfolgreich.

    Der PR hat einen zweiten Commit bekommen, die Zeile ist jetzt ein Listen-Eintrag. Labels: agent-revise raus, agent:revised rein.

    9. Stoppen¶

    Ctrl+C im Daemon-Terminal. Workspaces im ~/.agentry/workspaces/ werden automatisch aufgeräumt. PRs und Branches im Test-Repo bleiben — ggf. manuell mergen oder schließen.

    Was als Nächstes?¶

    • Service-Modus (Daemon im Hintergrund mit Auto-Restart): siehe Service-Modus. Empfohlen, wenn du Agentry tagelang am Stück laufen lassen willst.
    • Webhooks statt Polling für niedrigere Latenz: siehe Webhooks.
    • Parallele Worker für mehrere Tickets gleichzeitig: siehe Parallele Worker.
    • GitLab statt GitHub als Quelle: siehe GitLab-Source.

    Updates¶

    Während der Beta-Phase kommen regelmäßig neue Releases. Der Daemon prüft alle 24 Stunden automatisch gegen agentry-dist und loggt eine WARN-Zeile, wenn ein Update verfügbar ist:

    […] [WARN] [UpdateNotifier.swift] Update verfügbar: v0.1.0-beta.6 (lokale Version: 0.1.0-beta.5). Installation aktualisieren: `brew update && brew upgrade agentry`. Details: https://github.com/torben-erz/agentry-dist/releases/tag/v0.1.0-beta.6

    Manueller Check ohne Daemon-Restart:

    agentry update

    Update einspielen:

    brew update && brew upgrade agentry   # Tap-Cache neu holen, dann upgraden
# oder bei manuellem Download: neuen Tarball aus agentry-dist holen

    brew upgrade allein reicht nicht

    Der lokale Tap-Cache wird nur durch brew update aktualisiert. Ohne den Vorlauf zeigt brew upgrade agentry „already installed", obwohl agentry update bereits eine neuere Version meldet — siehe Troubleshooting.

    Details: Update-Notifier.

    Bug melden¶

    Während der Beta sammeln wir gezielt Feedback. Wenn etwas hakt:

    1. agentry diagnose ausführen — druckt einen kopierbaren Markdown-Block mit Version, Plattform, Tool-Verfügbarkeit, Sandbox- Status, Config-Health und den letzten 30 WARN/ERROR-Zeilen aus dem Log: 
      agentry diagnose | pbcopy   # macOS: direkt in die Zwischenablage
agentry diagnose            # alternativ: ausgeben und manuell kopieren
      Der Block enthält keine Tokens, Secrets oder Repo-Inhalte — sicher per Mail/Chat teilbar.
    2. Den Output zusammen mit einer kurzen Reproduktions-Schritt-Liste an bug-report@nanoapes.com schicken, oder den Bug als GitHub-Issue melden (falls dir das Repo freigegeben wurde).

    Was hilft besonders:

    • Was hast du erwartet? (1 Satz)
    • Was ist tatsächlich passiert? (1 Satz)
    • Welche Schritte führen zum Problem? (3–5 Zeilen)
    • Plattform (macOS-Version oder Linux-Distro)

    Was nicht ins Bug-Report gehört: Inhalt deiner privaten Repos, GitHub-Tokens, Notarisierungs-Tickets von Apple. Das brauche ich nie.
